## 第 21 个测量点的失败可复现

此点为第二轮的首频点，期望基带单音 2000 Hz。原记录有 3 帧，每帧 8192 个 IQ 样本，采样率 250 kS/s。

原正式测量窗可由 `iq[8192:18192]` 精确复现：10000 个样本、40 ms。旧函数只使用该窗末尾 2048 个样本，算得 1220.703125 Hz、−87.75774925 dB，与原表一致。完整 10000 样本参与 FFT 后，峰值为 2000.0 Hz、−84.66812656 dB。

完整正式窗的目标相干突出度为 17.9188 dB，目标对上一频点 21000 Hz 的优势为 19.8612 dB。它通过新增质量门限，但不能据此把历史 run 改为成功。

同点开始 20 ms 的 IQ 仍由上一单音 21000 Hz 主导：目标附近峰为 1450 Hz，目标相干突出度只有 0.6982 dB，目标相对上一单音为 −14.7811 dB。因此只修 FFT 截窗还不够，必须在切频后排除上一单音，并要求连续稳定验证窗。

## 独立复算与覆盖边界

使用不导入采集实现的 NumPy 复算器，按实际 v2 规则计算：完整 Hann 窗、至少 2048 点 FFT、目标附近 ±1000 Hz 峰频、误差严格小于 200 Hz、目标频率的相干系数相对邻域 FFT 幅度中位数至少高 6 dB、相对上一单音局部峰至少高 6 dB。邻域底噪估计排除目标与上一单音的主瓣。

- 全部 60 个原记录的幅度及峰频均可在已保存 IQ 中精确复现。
- 原正式 MEASURE 窗只有第 1、21、41 点达到 40 ms；其余 57 点短于 40 ms。不能称这些旧测量满足新增采集规则。
- 全部 60 个 NPZ 的末尾 40 ms 均通过新增的单窗质量检查。这只说明文件里有可用于离线检查的较长 IQ，并不等于原软件曾把它作为正式测量窗。
- 以 4 ms 步长检查同一个频点的连续 IQ，43 点存在通过门限的“20 ms 验证 + 20 ms 验证 + 40 ms 测量”序列。第 3、7、12、21、22、23、26、30、33、35、38、42、46、50、52、53、58 点未找到完整通过序列。此搜索不拼接跨点 IQ，不补样，也不据短窗外推。
- 将每点的全部已保存 IQ、首 20 ms、末 40 ms 共 180 个窗口与新增 `quality_measurement` API 对照，峰频和幅度完全一致；相干突出度及旧单音抑制差异最大约 `2.96e-12 dB`，通过／拒绝判定无差异。
- 固定随机种子的合成正负例中，目标单音通过；仅上一单音、错误单音、纯噪声、被上一单音压过的目标均拒绝。这是软件对照，不是硬件性能或统计误检率声明。

连续的软件帧索引不等于硬件时间戳连续性。上述离线窗口搜索也不是原采集线程调用时序的完整重演。新版完整流程、超时重试与真实链路仍须新实验验证；此报告不生成替代原始结果表，不宣称校准 S21、温度灵敏度或实验成功。

## 复用命令

在已激活的 `rf-gnuradio` 环境、项目根目录运行：

```sh
python -B tools/validate_sweep_iq_offline.py \
  Data/runs/20261031T084134_856931Z \
  --output /private/tmp/sweep_quality_offline_v2_recalculated.json
```

输出路径必须位于原 run 目录之外。默认 NumPy 复算不加载硬件模块。本报告的 180 窗 API 对照是在 v2 版本上完成；可选 `--compare-implementation` 只接受 v2，当前 v3 不适用该对照。新版完整状态机验证使用 `tools/replay_adaptive_sweep.py`，不要把旧门限参考算法与新版判据混为一谈。
