## 方法与边界

执行候选的真实 `SweepRunner.run`，只替换硬件切频、队列帧交付和时钟边界。单点重放向质量函数传入前一保存点的实际单音；没有重新实现状态转换。

每点从保存 IQ 下标 0 开始，按原 NPZ 的 `frame_lengths` 逐帧交付，检查 `frame_start_indices` 连续。帧可用时间为累计样点数 / 250000 Hz；8 秒截止时间不随拒绝或升级重置。所有实际消费窗连续且互不重叠。接受前必须有同档连续两窗 VERIFY，再使用另一段独立 MEASURE；频差仍严格小于 200 Hz。

这是理想采样时间回放，时钟不计 RF 调谐、USB、写盘、温压采集或 CPU耗时。CPU 墙钟单独计量；不能据此保证真机全程用时或 GUI 延迟。旧记录长度不足时明确标为不足，不能推断为候选成功或候选超时。原增益、发射幅度和历史人工温度标注均未改写。

## 复现

在仓库根目录使用既有 `rf-gnuradio` 环境：

```sh
python -B tools/replay_adaptive_sweep.py --all-points --output docs/sweep_adaptive_replay_20261031.json
```

可选 `--legacy-source /path/to/frozen/v2/logic.py` 重新生成 v2 对照；未提供时仅重放当前 v3。`--include-attempts` 可输出全部尝试，否则仅关键三个失败点保留完整候选尝试。数据按源文件和源码 SHA-256 溯源；脚本拒绝把输出写入 `Data`。
