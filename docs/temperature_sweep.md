# SSPP温度扫频：两个实验功能

顶部进入“SSPP温度扫频”，在侧栏选择模式。默认频段仍为5.0–5.3 GHz、20个等间隔载频，可按研究范围调整；这里只能筛选已扫频范围内的候选敏感频段。

## 手填温度 · 每个平台一次实验

1. 外部调整温度并等待稳定，填写条件名称及本次实测参考温度。
2. 初始化USRP，核对样品、接线、线缆与机械位置，确认后开始扫频。本模式不需要Arduino。
3. 按设置的轮数（默认3轮）完成本温度平台的一次记录，不设置整场总时限。需要提前结束时点击“停止并保存”，未完成的轮次保留为不完整；单点质量时限继续生效。
4. 调整到下一个温度，修改参考温度，再开始一条独立记录。

手填温度属于人工参考标签，不是自动传感器温度；每条记录的manifest、desktop_context和measurements.csv保存本次数值。完成且RF参数兼容的本模式记录可跨平台比较。历史双传感器平台记录保留兼容，不与新手填模式混为同一种量化比较。

## 连续变温 · 循环扫频与电压

1. 初始化USRP与Arduino，确认温度v1固件（9600波特，S6/S7）已验证。默认CH1/S6为温度关联通道，CH2/S7原始数据也保存。
2. 样品、SSPP、传感器、接触条件及线缆位置固定。加热由外部设备控制，软件允许温度持续变化，不等待30秒稳态窗口。
3. 设置频段和频点数；本模式忽略“重复轮数”，不设置整场总时限，持续完成一轮又一轮扫频，直到点击“停止并保存”。单点质量时限与原有自适应质量算法继续生效。
4. 点击“开始连续变温循环扫频”，Arduino先取得有效递增样本，再启动RF。两类数据在同一次记录中持续保存。
5. 主视图显示最近32轮扫频曲线、电压时间曲线和最近100轮区间统计；历史／导出保存全部实际记录，显示裁剪不删除数据。
6. 停止后查看候选敏感频点排名与斜率曲线，下载完整CSV。至少3个有效完整扫频区间，且各轮代表电压／温度有不同取值，才计算探索性排名。

“一个扫频区间”是从本轮第一个频点开始到最后一个频点结束的一轮完整扫频（不是3轮整体）。该区间中所选通道全部实收电压做算术均值，并保存样本数、样本SD、最小／最大值、跨度、区间起止和时长。区间边界使用主机单调时间与串口接收时间，不宣称硬件同步或RF积分窗内精确温度。

## 用平均电压换算温度

当前已有线性换算接口：启用“使用已完成标定的温度换算”，填写真实标定编号、T=k×V+b的系数和有效电压范围，系数在实验开始时冻结。整轮代表温度使用T(该轮平均电压)，全部区间样本都在有效范围内才记录该温度；任何样本越界则该轮温度留空，不外推。

未启用有效标定时仍可连续采集、以平均电压关联曲线并筛选dB/V候选频点；不会臆造℃。启用有效标定后排名单位为dB/℃。系数须来自用户实际标定，本功能不自动生成系数或由首尾温度按时间补造标签。

## 如何寻找影响较大的频段

每个载频／单音组合分别建立幅度与各轮代表温度（或未标定电压）的关系，输出线性斜率、斜率绝对值排名、R²、幅度跨度、自变量跨度及观测轮数。未完成末轮、样本不足／明显缺口／复位或关联丢失的区间不纳入排名；有标定但无法有效换算的轮次也排除。不同温度状态的轮次不再被当作同温重复测量来报告重复SD，连续模式也不套用旧的跨run均值相减比较。

排名用于选候选频段，不等于已证实温度因果、校准S21或独立温度灵敏度。一轮内温度持续变化时，平均值仅是代表标签，曲线并非恒温测得；必须同时检查轮内电压跨度和每点当时的电压。固定扫频方向可能与升温时间混淆，候选频段应再用较慢升温、不同扫描顺序或手填稳态平台实验独立复验。没有足够状态变化时不应解释微小电压漂移对应的大斜率为高灵敏度。

## 数据文件和停止

每次仍保存在 `Data/runs/<run_id>/`。手填模式保存常规RF文件及人工温度元数据；连续模式另保存：

- `temperature/raw_serial.bin`、`temperature/samples.csv`、事件与manifest：双路原始串口及停止证据。
- `temperature_measurements.csv`：每个RF频点关联的最新实收电压、样本年龄、RF质量窗口及时间，不把单样本当区间均值。
- `temperature_rounds.csv`：每轮时间区间、平均电压、SD／跨度、换算温度与完整性。
- `temperature_intervals.json`：完整区间统计、冻结标定与分析限制。
- `frequency_sensitivity.csv`：候选频点排名，含载频及单音频率。
- 常规 `measurements.csv`、分点IQ、`sweep_quality.jsonl`、结果和图表继续保存；输出图最多画最近32轮，完整表不裁剪。原始IQ是否打包仍由用户选择，串口与分析文件随实验包导出。

手动停止是连续模式的正常结束条件，不再因整场记录时长而自动结束。最后未扫完的一轮保留并明确标记partial，不纳入完整曲线排名；至少一轮完整且无采集错误、双侧停止／封存证据完整时本次采集才可完成。串口过期／断连／复位、存储或其他硬件错误仍使记录失败／不完整。持续收到IQ但单点8秒内未取得合格测量时，该点保留为空缺并继续；扫描结束含无效点则显示“已结束（含无效频点）”，不静默放宽门槛。持续变温本身不作为错误，也不因电压变化自动中止。

界面不再提供扫频总时限或“自动预留总时限”控件。旧草稿中的`max_seconds`及`auto_sweep_budget`不会恢复总时限；旧API配置中的`max_seconds`归一为`None`。单点时限、通信故障处理和停止封存要求保持；连续幅相实验自身的记录时长设置也保持。

启动、切换模式及查看历史不会自动探测、发射或烧录。仍需用户现场确认后开始真实实验。本次验证为软件与模拟设备验证，真实长时双传感器联测及温度效果待验收。

## 温压页电压可见性修复

原温压页也补上自动跟随、恢复全图、当前电压数值和单通道查看，每次新记录重置视野。用户提供的 `20261031T082508_370073Z` 历史记录含 1698 行有效样本，CH1 4.149–4.156 V，CH2 2.712–2.722 V；离线重放可见曲线，截图视野未覆盖实测电压。那次失败标签含启动时旧半行与固件横幅拼接事件。新解析保留该事件和原始字节、排除非测量残片，不修改旧记录的状态或内容。

## 验证边界

软件回归、模拟串口、模拟 RF 生命周期、历史数据重放验证与真实硬件实验分别记证据。本轮未自动初始化设备、烧录或发射；真实双传感器联测及温度变化结果由现场开始实验后验证。


## 弱信号缺测点（2026-11-02修复）

最长自适应窗口为2秒，默认每点8秒上限不变。候选敏感频段分析跳过无效RF点，但可继续使用同轮其他有效点；含无效点的一轮会明确标记，不能把空缺看成极深谐振。原始电压、IQ、拒绝原因和实际扫描网格均保留。详见 [窗口与质量策略](sweep_quality.md)。
